# 시간 시스템과 UI 연동 인수인계서

작성: 하종욱 · 2026-11-18

## 현재 구현과 소유권

`StoreUiSessionController`의 영업 카운트다운이 시간의 기준이다. `UiBusinessTimeBridge`는 UI의 일차 시작 이벤트와 남은 시간을 읽어 `BusinessTimeController`의 진행률을 0~1로 동기화한다. 하늘·태양·달·날씨는 그 시계의 게임 시각을 사용한다. UI가 정산을 시작하면 브리지는 진행률을 1로 맞추고 시간 시스템의 해당 일차를 정산 완료로 표시한다. 정산 API를 두 번째로 호출하지 않는다.

브리지는 `AcquireExternalClock`으로 외부 시간 소유권을 선점하며 데모 시계와 독립 시계의 동시 실행을 막는다. UI의 일차 번호가 재시도 때 1로 초기화될 수 있으므로 시간 시스템 내부 DayId는 새 세션마다 증가한다. 로비로 돌아가면 진행 중인 시간 일차를 취소 상태로 정리한다. 중첩 커서 잠금은 `PlayerUiCursorLockAdapter`가 관리하며 시간 일시정지와 별개다.

## 씬 구성

검증 씬: `Assets/_Project/HaJongUk/Scenes/HJU_Time_UI_Integration.unity`. 팀 UI 프리팹, EventSystem, 플레이어, 시간 시스템, 브리지가 연결돼 있다. 시간 테스트 패널과 이동 테스트 패널은 중복 UI를 피하도록 비활성화돼 있다. 기존 작업 씬은 변경하지 않았다.

다른 씬에서 연결할 때는 시간 시스템의 독립 시계를 끄고 `UiBusinessTimeBridge`의 **영업 UI**와 **시간 시스템**을 지정한다. UI의 `externalCursorLockGateComponent`에는 플레이어의 `PlayerUiCursorLockAdapter`를 지정한다. UI 인스턴스가 런타임에 생성된다면 두 참조가 준비된 뒤 브리지의 `Configure(ui, clock)`을 호출한다. 이미 진행 중인 데모 시계를 외부 시계로 전환하지 않으며, 연결 실패 시 콘솔 오류를 확인한다. 동일 시간 시스템에는 브리지를 하나만 둔다.

### 씬 연동 시 NavMesh 확인

시간·UI 연동과 손님이나 직원의 이동용 내비게이션은 별개다. 씬을 복사하거나 매장 맵을 교체한 뒤에는 `NavMeshSurface`에 해당 씬의 이동 가능한 바닥과 장애물이 포함되는지 확인하고, 이동 영역을 다시 베이크해 유효한 NavMesh 데이터를 연결한다. 맵이 바뀌면 기존 데이터가 새 지형과 일치하는지도 확인한다. 원본 씬과 서로 다른 맵을 사용하는 경우에는 데이터 에셋을 따로 관리해 한 씬의 재베이크가 다른 씬에 영향을 주지 않도록 한다.

Play 전에 `NavMeshAgent`가 활성화될 위치가 베이크된 이동 가능 영역 위에 있는지 확인한다. Play 후에는 콘솔의 `Failed to create agent because there is no valid NavMesh` 오류가 없는지, 에이전트가 NavMesh에 올라와 실제 목적지까지 이동하는지 확인한다. 오류가 발생하면 Surface의 데이터 연결, 수집 대상·레이어, 바닥의 위치와 에이전트 시작 위치를 차례로 점검한다. 이 오류만으로 시간·UI 연동 자체가 실패했다고 판단하지 않는다.

**현재 확인된 사항:** 저장된 `HJU_Time_UI_Integration` 씬의 `NavMeshSurface`에는 NavMesh 데이터가 연결되어 있지 않다. 따라서 이동 에이전트를 사용하는 통합 테스트 전에 해당 씬의 데이터 베이크와 연결을 완료해야 한다. 이 문서 수정만으로 씬의 오류가 해결된 것은 아니다.

## 테스트 방법

1. Unity에서 위 검증 씬을 열고 Play를 누른다. 로비에서 게임을 시작한다.
2. UI 시간 감소와 하늘·조명의 변화를 함께 확인한다. 기본 UI 하루 길이는 180초이며 시간 테스트 전용 60초와 구별한다.
3. Tab 명령창과 Esc 닫기, 로비·정산 화면에서 커서와 시점 잠금을 확인한다. UI 잠금만으로 영업 시간이 정지하지 않는다.
4. UI 시간이 종료되면 정산이 한 번 표시되는지, 다음 일차 또는 재시도 때 시간과 낮밤이 시작값으로 돌아가는지 확인한다. 로비 복귀 후 재시작도 확인한다.
5. 빠른 검증에서는 런타임에 `StartDay(1, 50000, 2)`로 짧은 일차를 시작할 수 있다. Play 종료 후 원래 씬 데이터는 유지된다.

2026-11-18 Unity 6000.6.4f1 Editor 검증: 실제 UI 프리팹과 저장된 통합 씬에서 중간 진행률 0.50, 마감 이벤트 1회, 정산 상태, 다음 일차 및 로비 재시작, 데모 시계 중복 차단을 확인했다. Player 빌드는 아직 확인하지 않았다.

## 남은 연동

현재 UI는 타이머 종료 시 `CompleteDayAndShowSettlement`를 직접 호출한다. 손님 입장 중단, 진행 중 거래 정리·제한시간, 최신 직원 상태의 최종 동결과 실제 매장 데이터 연결은 담당 시스템과 통합해야 한다. 현재 UI 프리팹의 직원 스냅샷은 기본값일 수 있으므로 이를 실제 직원 값으로 보장하지 않는다. 일시정지 화면과 저장/불러오기도 별도 통합 대상이다. 이 항목을 완료된 기능으로 간주하지 않는다.
