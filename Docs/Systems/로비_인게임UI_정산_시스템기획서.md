## 1. 목적과 검증할 경험

플레이어가 1인칭 시점으로 편의점을 운영하는 동안 **음성(또는 보조 텍스트) 명령의 처리 진행 상태**, **직원의 성격·감정·이동 상태**, **일차 영업 시간과 보유 자금**, 그리고 **영업 종료 후 수행 시간·감정 비례 정산 결과**를 화면에서 직관적으로 확인하고 조작할 수 있는 최소 UI 및 정산 기반을 구축한다.

특히 초기 검증에서 확인된 두 가지 위험 요소를 UI에서 해결한다.
1. **로컬 STT·LLM 처리 지연 체감 완화**: 음성 녹음 종료부터 행동 코드 판정까지 시간이 걸릴 때 화면에 진행 단계(`음성 인식 및 AI 판단 중...`)를 명확히 표시해 멈춤 현상으로 오해하지 않게 한다.
2. **명령 실패 원인의 3종 분리 안내**: ① 단순 인식 실패·미지원 명령, ② 직원 감정 악화로 인한 의도적 거부, ③ 모델·통신·이동 시스템 오류를 서로 다른 색상과 문구로 구분해 플레이어가 다음 판단(재지시 / 대기 회복 / 복구 확인)을 내릴 수 있게 한다.

첫 검증 장면은 **“로비에서 게임 시작 → 인게임 HUD에서 직원 상태·남은 시간 확인 및 보조 명령창/시뮬레이션으로 지시 전달 → 감정·누적 작업 시간 반영 확인 → 일차 종료 후 정산 내역 및 결과 등급 확인”**이다.

## 2. 첫 개발 범위 (1차 시제품 MVP)

| 구분 | 1차 시제품 포함 (Must-Have) | 제외 · 후속 확장 (Later) |
| :--- | :--- | :--- |
| **로비 UI** | 타이틀 표기, `게임 시작` / `게임 종료` 2개 버튼 | 마이크 입력 장치 선택, 음량·감도 설정, 세이브 슬롯 |
| **인게임 상시 HUD** | 일차·남은 영업 시간·현재 자금 표시, 직원 1명 상태 카드(`이름`, `성격`, `현재 행동`, `이동 상태`, `스트레스·피로도·충성도` 바), 하단 음성 처리 단계 및 인식 문장 표시줄, 3종 오류 구분 배너 | 다수 직원(n명) 동시 카드 목록, 미니맵, 손님 대기열 알림 |
| **보조 명령 입력창** | 단축키(`Tab`) 또는 버튼으로 여닫는 한국어 텍스트 명령 입력창(`InputField`), 전송 버튼, 시제품 빠른 지시(`계산`, `진열`, `취소`) 버튼 | 직원별 개별 호출 드롭다운, 세부 업무 우선순위 보드 |
| **일차 정산 및 결과** | 수행 시간 × 감정 효율 계수 기반 매출·원가·운영비·최종 잔액 산출, 진열 부족 패널티 표기, 1회 정산 보장, 시제품 3분기 결과 화면 및 재시작/로비 복귀 | 다중 일차(`1~7일`) 상점 발주·고용 화면, 캐릭터별 컷신 및 장문 후일담 연출 |
| **외부 연동 경계** | 카메라·이동 입력 잠금(`ICursorLockGate`), 외부 음성·AI 상태 수신 API, 텍스트 명령 전달 이벤트 | `whisper.unity` 녹음 자체(`이승재` 담당), 1인칭 이동·경로 탐색 자체(`하종욱` 담당) |

## 3. 사용 상황 및 화면 전환 흐름

```
[로비 화면 (Lobby)] ──(게임 시작)──▶ [인게임 상시 HUD (InGame)]
        ▲                                  │  ▲
        │                      (Tab / 보조 입력 열기 · 닫기)
        │                                  ▼  │
        │                       [보조 텍스트 명령창 (CommandOverlay)]
        │                                  │
        │                        (영업 제한 시간 종료)
        │                                  ▼
        └──(로비로 복귀)─────── [일차 정산 및 결과 화면 (Settlement)]
```

1. **로비 진입 시**: 커서가 활성화된 상태로 `게임 시작`과 `게임 종료` 버튼만 간결하게 표시한다.
2. **인게임 기본 플레이 시**: 1인칭 시야 중앙을 가리지 않도록 상단(운영 정보), 우측 상단(직원 상태), 하단(음성·명령 피드백) 가장자리 중심으로 HUD를 배치하며, 마우스 커서는 잠금 상태(1인칭 시점 회전 가능)를 유지한다.
3. **보조 명령 입력창 오픈 시**: 마이크 사용이 어렵거나 오인식 시 즉시 재지시할 수 있도록 `Tab` 키를 누르면 입력 오버레이가 열리고 플레이어 시점·이동 잠금 토큰을 획득한다. 명령 전송 또는 `Esc`/`Tab`/닫기 클릭 시 잠금 토큰을 해제하고 1인칭 시점으로 복귀한다.
4. **일차 영업 종료 시**: 제한 시간(`기본 180초`)이 `0`이 되면 즉시 정산을 1회 확정하고 정산 화면을 열며, 시점·이동 잠금 토큰을 획득해 마우스로 결과를 확인하고 재시작 또는 로비 복귀를 선택한다.

## 4. 세부 동작 규칙

### 4.1 음성·명령 처리 단계 및 3종 예외 표시 규칙
| 구분 | 발생 조건 | 화면 표시 규칙 | 플레이어 유도 행동 |
| :--- | :--- | :--- | :--- |
| **대기 (`Idle`)** | 음성 입력 대기 중 | 기본 안내 문구(`음성 지시 대기 중 · [Tab] 텍스트 지시`) 표시 | 마이크로 말하거나 `Tab`으로 텍스트 지시 |
| **녹음 중 (`Listening`)** | 마이크 입력 감지 중 | 청록색 배지(`듣는 중...`) 표시 | 명령 발화 진행 |
| **처리 중 (`Processing`)** | STT 변환 및 LLM 행동 판정 중 | 하늘색 배지 + 점 애니메이션(`음성 인식 및 AI 판단 중...`) 표시 | 처리 완료까지 대기 (멈춤 오해 방지) |
| **수락 (`Accepted`)** | 허용 행동 코드로 정상 판별 | 초록색 피드백 배너 + 인식 문장 및 수락 행동 표시 | 직원의 이동 및 업무 수행 관찰 |
| **① 단순 인식 실패 (`RecognitionFailed`)** | 불명확 발화 · 미지원 업무 | **노란색 경고 배너** (`인식 실패/미지원 명령 — 다시 말씀해 주세요`) | 재발화 또는 `Tab` 보조 입력 사용 |
| **② 감정 악화 거부 (`RefusedByEmotion`)** | 스트레스·불만 임계로 거부 | **붉은색 거부 배너** (`직원이 불만/분노 상태로 지시를 거부했습니다!`) | 추가 재촉 중단 및 대기(`Idle`) 회복 유도 |
| **③ 시스템·이동 오류 (`SystemOrMoveError`)** | 모델 부재·지연 초과·경로 실패 | **주황/회색 시스템 배너** (`시스템/이동 오류 — 기본 대기로 복구합니다`) | 장애물·상태 확인 후 재지시 |

### 4.2 직원 상태 카드 표시 규칙
- 이승재 담당 AI 시스템의 입력 스탯과 하종욱 담당 이동 시스템의 상태를 한 카드에 통합 표시한다.
  - **기본 정보**: 직원 이름, 성격 표기, 현재 수행 행동명(`대기` / `계산` / `진열` 등), 이동 상태 배지(`대기` / `이동 중` / `도착` / `실패` / `취소`).
  - **3종 수치 바 (`0 ~ 100`)**:
    - `스트레스`: `0~39`(안정·초록), `40~79`(피로·불만·노랑), `80~100`(분노·임계·빨강)으로 게이지 색상을 즉시 변경해 위험도를 직관적으로 알린다.
    - `피로도`: `0~100` 주황 계열 게이지 표시.
    - `충성도`: `0~100` 파랑 계열 게이지 표시.

### 4.3 일차 정산 및 결과 판정 규칙 (Core 순수 계산)
- **수행 시간 × 감정 효율 비례 계산**:
  - 스트레스 구간별 작업 효율 계수: 안정(`0~39`) `1.0x`, 피로·불만(`40~79`) `0.8x`, 분노·임계(`80~100`) `0.5x`.
  - `유효 계산 시간` × 초당 계산 기준 매출(`기본 800원`) + `유효 진열 시간` × 초당 진열 기준 매출(`기본 500원`)로 기본 매출을 계산한다.
  - `유효 진열 시간`이 최소 기준(`기본 25초`) 미만이면 총 기본 매출에 `0.8x`(20% 감산) 패널티를 적용한다.
  - `최종 잔액 = 기초 자금(50,000원) + 당일 최종 매출 - (상품 원가 30% + 고정 운영비 25,000원)` (반올림 정수 원 단위).
- **중복 정산 방지**: 한 일차 세션에서는 정산 확정 함수를 한 번만 실행하며, 정산 이후 추가 시간 경과나 재호출로 잔액이 중복 가산되지 않는다.
- **시제품 3분기 결과 등급**:
  1. `안정 운영 성공`: 목표 잔액(`80,000원`) 이상 달성 & 종료 스트레스 `80` 미만(분노 거부 `2회` 이하)
  2. `불안정 성공 (분노 누적)`: 목표 잔액(`80,000원`) 이상 달성했으나 종료 스트레스 `80` 이상 또는 분노 거부 `3회` 이상 발생
  3. `목표 미달 실패`: 최종 잔액이 목표 잔액(`80,000원`) 미만

### 4.4 플레이어 입력 잠금 및 커서 소유권 규칙
- UI가 마우스 클릭·키보드 타이핑을 점유하는 상태(`로비`, `보조 텍스트 명령창 열림`, `일차 정산 화면 열림`)에서는 외부 입력 잠금 계약(`ICursorLockGate.AcquireLock(reason)`)을 통해 토큰을 획득하고, 해당 창이 닫히거나 비활성화(`OnDisable`)될 때 반드시 `Dispose()`한다.
- 공용 통합 시 하종욱 담당 `PlayerRigController.InputGate`를 어댑터로 연결하며, 그 경우 **UI 컴포넌트가 `Cursor.lockState`나 `Cursor.visible`을 직접 덮어쓰지 않는다.**
