## 1. 목적과 검증할 경험

플레이어가 1인칭 시점으로 매장을 운영하는 동안 **음성(또는 보조 텍스트) 명령의 처리 진행 상태**, **알바 직원의 성격·감정·이동 상태(HUD 및 3D 머리 위 말풍선)**, **일차·남은 영업 시간·현재 및 목표 금액**, 그리고 **영업 종료 후 매출·지출 정산과 알바 상태 결산**을 화면에서 직관적으로 확인하고 조작할 수 있는 UI 및 정산 시스템을 구축한다.

특히 다음 세 가지 핵심 과제를 해결한다.
1. **로컬 STT·LLM 처리 지연 체감 완화**: 음성 녹음 종료부터 행동 판정까지 시간이 걸릴 때 화면에 진행 단계(`음성 인식 및 AI 판단 중...`)를 명확히 표시해 멈춤 오해를 막는다.
2. **명령 실패 원인의 3종 분리 안내**: ① 단순 인식 실패·미지원 명령, ② 직원 감정 악화로 인한 거부/태만, ③ 시스템·이동 경로 오류를 색상과 문구로 구분해 플레이어의 다음 행동을 유도한다.
3. **1차 통합 데모(`1일차`)에서 본편(`0~7일차`)으로 자연스럽게 확장되는 화면·정산 구조**: 단일 일차 시제품 검증을 즉시 수행하면서도, `인트로 → 0일차(알바 설정·튜토리얼) → 1~7일차 영업(조기 마감 포함) → 3단 정산·정비(매출 결산 / 알바 상태 / 자금 소비) → 최종 멀티 엔딩`으로 코드 파괴 없이 확장되도록 구성한다.

## 2. 개발 범위 구분 (1차 통합 데모 구현 완료분 vs 2차 본편 확장)

| 구분 | 1차 통합 데모 포함 (현재 기반 구현 완료) | 2차 본편 확장 (전체 게임 흐름 반영) |
| :--- | :--- | :--- |
| **도입 · 로비 UI** | 메인 로비(`[게임 시작]`, `[환경 설정]`, `[게임 종료]`), 환경 설정 창(볼륨·마이크 장치·마우스 감도) | 최초 실행 **인트로 스토리 화면(스킵 지원)**, **`0일차` 알바 페르소나 설정 창 & 조작 튜토리얼** |
| **인게임 상시 HUD** | 상단(`현재 일차`, `남은 시간`, `현재 금액 / 목표 금액`), 우측 알바 상태 카드(`이름`, `성격`, `현재 업무`, `이동 배지`, `스트레스·피로·충성도` 바), 하단 음성 지연 표시 및 반응 대사·3종 오류 배너, `Esc` 일시정지 메뉴 | 일차별 **추가 미션(청소·발주) 및 기상/방해 효과 알림 아이콘**, **임의 조기 마감 버튼(확인 팝업)** |
| **월드 UI (3D)** | 알바 머리 위 빌보드 상태 헤더 및 반응 한 줄 말풍선 (`PF_EmployeeWorldStatusUI`) | 손님 NPC 주문/대기 아이콘, 매장 내 상호작용(사장 직접 계산 포스기·청소 지점) 프롬프트 |
| **보조 명령 입력창** | `Tab` 키로 여닫는 한국어 텍스트 명령창, 빠른 지시(`계산`, `진열`), `작업 취소/휴식` | 해금된 추가 업무(`청소` 등) 빠른 지시 버튼 동적 노출 |
| **일차 정산 · 정비** | 수행 시간 × 감정 효율 기반 매출·원가·고정비·진열 부족 패널티 1회 정산, 3등급 결과창(`재시도`/`로비 복귀`) | **3단 정산 전환**: ①매출·알바 계산 수당 결산 → ②알바 상태 리포트 → ③보유 자금 소비(물품 발주·알바 케어) 후 `다음 일차(x+1일차)` 진입, `7일차` 종료 시 **4대 멀티 엔딩 화면** 연결 |

## 3. 화면 전환 흐름

### 3.1 1차 통합 데모 화면 흐름 (현재 동작 중)
```text
[로비 화면 (게임 시작 / 설정 / 종료)] ──(게임 시작)──▶ [1일차 인게임 HUD + 3D 월드 말풍선]
        ▲                     │                              │            │
        │                  (설정)                     (Tab: 보조 명령창) (Esc: 일시정지/설정)
        │                     ▼                              │            │
        │               [환경 설정 창] ◀─────────────────────┴────────────┘
        │                                                    │
        │                                          (제한 시간 00:00 종료)
        │                                                    ▼
        └──────────────(로비 복귀 / 재도전)───────── [1일차 정산 결과 화면]
```

```text

                                                                 │
                                                      [1일차 오픈 전환 연출]

                ┌──────────────────────────────▶ [Day 1 ~ 7 인게임 영업 HUD]
                │                                  │  (시간 종료 또는 조기 마감)
                │                                  ▼
                │                        [정산 1화면: 당일 매출·인건비·목표 정산]
                │                                  │  (클릭 / 다음 버튼)
                │                                  ▼
                │                        [정산 2화면: 알바 스트레스·감정 상태 리포트]
                │                                  │
     (Day 1~6: 자금 소비·발주·케어 후 다음 날) ────┼──── (Day 7 종료 또는 파산/폭주)
                                                   ▼
                                         [최종 멀티 엔딩 & 후일담 화면] ──▶ [메인 로비]
```

## 4. 세부 동작 및 정산 규칙

### 4.1 음성·명령 처리 단계 및 3종 예외 표시 규칙
| 구분 | 발생 조건 | 화면 표시 규칙 | 플레이어 유도 행동 |
| :--- | :--- | :--- | :--- |
| **대기 (`Idle`)** | 음성 입력 대기 중 | 기본 안내 문구(`음성 지시 대기 중 · [Tab] 텍스트 지시`) 표시 | 음성 발화 또는 `Tab` 보조 입력 사용 |
| **녹음 중 (`Listening`)** | 마이크 입력 감지 중 | 청록색 배지(`듣는 중...`) 표시 | 명령 발화 진행 |
| **처리 중 (`Processing`)** | STT 변환 및 LLM 행동 판정 중 | 하늘색 배지 + 점 애니메이션(`음성 인식 및 AI 판단 중...`) 표시 | 처리 완료까지 대기 (멈춤 오해 방지) |
| **수락 (`Accepted`)** | 허용 행동 코드로 정상/불만 수락 | 초록색 피드백 배너 + 알바 반응 대사 및 월드 말풍선 출력 | 직원의 이동 및 업무 수행 관찰 |
| **① 단순 인식 실패 (`RecognitionFailed`)** | 불명확 발화 · 미지원 업무 | **노란색 경고 배너** (`인식 실패/미지원 명령`) | 재발화 또는 `Tab` 보조 입력 사용 |
| **② 감정 악화 거부 (`RefusedByEmotion`)** | 스트레스 임계로 정면 거부 또는 태만 | **붉은색 거부 배너** + 거절 대사 출력 | `휴식(쉬어)` 지시 또는 사장 직접 보조로 진정 유도 |
| **③ 시스템·이동 오류 (`SystemOrMoveError`)** | 모델 부재·지연 초과·경로 실패 | **주황색 시스템 배너** (`시스템/이동 오류 — 대기 복구`) | 장애물·상태 확인 후 재지시 |

### 4.2 일차 정산 공식 및 본편 확장 구조 (`Core` 순수 계산)
1. **기초 자금(`a원`) 지급 및 이월**:
   - `0일차` 오픈 준비 시 기본 자금 `a원`(`1차 데모 기준 50,000원`)이 지급된다.
   - 본편(`Day 1~7`)에서는 당일 최종 잔액이 다음 날 시작 자금으로 이월되며, 일차 사이 정비 화면에서 발주·케어 비용으로 소비할 수 있다.
2. **매출 및 지출 산식**:
   - **1차 통합 데모 (시간 비례 정산)**:
     - 스트레스 구간별 작업 효율 계수: 안정(`0~39`) `1.0x`, 피로·불만(`40~79`) `0.8x`, 분노·임계(`80~100`) `0.5x`.
     - `유효 계산 시간 × 초당 계산 매출` + `유효 진열 시간 × 초당 진열 매출` (최소 진열 시간 미달 시 `-20%` 감산 패널티).
     - `최종 잔액 = 시작 자금 + 당일 최종 매출 - (상품 원가 30% + 고정 운영비)`.
   - **2차 본편 확장 (손님 계산 횟수 & 사장 직접 계산 반영)**:
     - 손님 NPC 결제 완료 시 판매 금액이 당일 매출에 가산된다.
     - **알바가 계산한 경우**: 내부에서 **알바 계산 횟수**를 누적 저장했다가, 일차 정산 시 `알바 기본 일급 + (계산 횟수 × 건당 수당)`을 지출 항목으로 차감한다.
     - **사장(플레이어)이 직접 계산한 경우**: 알바 건당 수당은 지출되지 않으나, 사장 계산 속도가 느리고 알바 성향·상태에 따른 감정 변화가 반영된다 ([전체 게임 흐름 기획서 3.3절](전체_게임흐름_및_일차루프_기획서.md) 기준).
3. **임의 조기 마감 처리 및 중복 정산 방지**:
   - 시간 만료(`00:00`) 또는 플레이어의 **임의 조기 마감**(돌발 사건 미발생·최소 경과 시간 충족 시) 시 `SettleOnce`를 통해 **단 1회만 정산을 확정**하며, 조기 마감 시에도 당일 고정 운영비는 동일하게 차감한다.

### 4.3 플레이어 입력 잠금 및 커서 소유권 규칙
- UI가 마우스 클릭·타이핑을 점유하는 상태(`로비`, `0일차 설정`, `보조 텍스트 명령창`, `일시정지 메뉴`, `환경 설정 창`, `정산 및 엔딩 화면`)에서는 `ICursorLockGate.AcquireLock(reason)` 토큰을 획득하고, 닫히거나 비활성화(`OnDisable`)될 때 반드시 `Dispose()`한다.
- 공용 통합 시 하종욱 담당 `PlayerRigController.InputGate`를 어댑터로 주입하며, UI 컴포넌트가 `Cursor.lockState` / `Cursor.visible`을 직접 덮어쓰지 않는다.
