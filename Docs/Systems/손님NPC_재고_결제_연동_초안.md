# 손님 NPC · 재고 · 결제 연동 초안

대상은 `NpcPopulationController`다. 11월 23일 Unity 테스트 씬의 플레이 모드에서 재고 거부 시 질문과 퇴장, 위치 안내 후 상품 집기, 외부 결제 승인과 다음 손님의 계산대 진입, 자동 계산 모드를 확인했다. 질문 대상과 응답은 테스트 중 임시로 연결했다. 실제 재고·포스기·직원·정산 연동은 별도 검증이 필요하다.

1. 연동 담당자가 `WaitForExternalCheckout = true`로 설정한다. 기본값은 기존 테스트를 위한 자동 계산이다.
2. `CanTakeFromShelf`에 `Func<string, bool>`을 연결하면 상품 선택과 집기 직전에 카테고리 태그로 재고를 조회한다. 이 함수는 조회 전용이다. 집기에 성공하면 `ProductPickedUp` 이벤트가 `(customerId, tag)`를 전달한다. 재고 소유자가 이벤트에서 재고를 한 번 차감하고 매출은 아직 올리지 않는다. 태그는 품목 고유 ID가 아닌 카테고리이므로 매대별 또는 SKU별 차감은 별도 식별자 연동이 필요하다.
3. `TryGetCurrentCheckout(out int customerId, out string productTag)`가 true이면 해당 손님이 계산대에 도착해 외부 승인을 기다리는 중이다. 포스기 또는 직원의 결제 성공 시 매출·판매 내역을 담당 시스템에서 확정하고 `TryCompleteCurrentCheckout(out int customerId)`를 호출한다. 승인은 한 번만 수락된다. 실제 판매 처리와 승인 사이의 실패·중복 방지 계약은 거래 ID와 함께 담당자 간 확정해야 한다.
4. 실제 재고 감소, 진열 보충, 매출 증가, 영수증·정산 UI는 이 컨트롤러가 수행하지 않는다. 품목별 가격을 위한 SKU 및 집기 취소·중도 퇴장 시 재고 복구 방식도 협의가 필요하다.

## 상품 탐색과 질문

직행 손님은 입장 후 상품을 고르고 해당 진열대로 이동한다. 고민하는 손님은 통로에 잠시 멈춰 상품을 고른다. 선택을 망설이는 손님은 매장 안쪽 통로에 더 오래 머문 뒤 선택한 상품으로 이동한다. 입장 지점에서 고민하다가 구매 없이 나가는 손님도 있다. 정해진 상품을 찾는 손님은 탐색을 끝내도 찾지 못하면 유형에 따라 직원 또는 플레이어에게 묻거나 그대로 퇴장한다.

`CustomerAskedForProduct`는 `(customerId, productName, 대상 Transform)`을 전달한다. 응답자는 `TryAnswerProductQuestion(customerId, 위치 Transform)`으로 위치를 안내할 수 있다. 응답이 없거나 시간 안에 확보할 재고가 없으면 구매를 포기하고 퇴장한다. 테스트 씬에는 직원과 플레이어 역할의 질문 위치, 품절 상품 한 종과 최근 질문 표시가 있다. 실제 응답 UI와 재고 처리 방식은 담당 시스템과 연동한다.
