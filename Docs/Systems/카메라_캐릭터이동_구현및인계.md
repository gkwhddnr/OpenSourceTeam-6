# 카메라·캐릭터 이동 구현 및 인계

## 실행 방법
Unity 6000.6.4f1에서 다음 씬 중 하나를 열고 Play한다.
- 개인 검증: Assets/_Project/HaJongUk/Scenes/HJU_CameraMovement_Work.unity
- 공용 통합: Assets/_Project/Shared/Scenes/Team_Integration.unity

WASD 이동, 마우스 시점, Esc 커서 해제, 클릭 커서 잠금.
숫자 윗줄 또는 숫자 키패드의 1·2·3은 직원의 Target_1·2·3 이동, C는 현재 이동 취소다. 공용 씬은 1·2만 연결되어 있다. Target 위치는 WorkDestinations의 각 오브젝트에서 수정하고 MovementDemo의 Destinations 배열에서 연결한다.
MovementDemo 오브젝트는 검증용 표시와 명령 입력을 제공한다. 실제 UI 연결 시 비활성화한다.

## 구현 구조
소스는 Assets/_Project/HaJongUk/Scripts 아래 Camera와 Movement로 나눈다.
Core는 엔진 참조 없는 규칙·좌표·요청·잠금 계약이며 Unity 계층은 엔진 연결부다.
.asmdef로 컴파일되는 자체 어셈블리를 사용하며 생성 DLL을 소스 폴더에 복사하지 않는다.
플레이어 프리팹에는 Renderer가 없으며 눈높이는 1.6m, 충돌 높이는 1.8m다.
직원은 NavMeshAgent만 위치를 작성한다. 씬마다 독립 NavMesh를 저장했다.

## 다른 담당자 연결
Movement.Core와 Movement.Unity를 사용하는 담당 어셈블리의 참조에 추가한다.
직원 컴포넌트를 Inspector로 주입받아 IAgentMovement로 사용한다.
RequestMove(WorldPoint)는 수락 여부와 요청 ID를 반환한다.
Finished는 LateUpdate에서 MoveOutcome을 전달한다. RequestId를 비교하고
Status, Failure, Cancellation을 구분한다. 구독은 OnDisable에서 해제한다.
Cancel(id)는 현재 요청만 취소한다. 잘못된 새 목적지는 기존 요청을 취소하지 않는다.
모든 API는 Unity 메인 스레드에서 호출한다. 일반 NPC 행동·음성·FSM은 후속 연결 대상이다.
UI 조작 잠금은 PlayerRigController.InputGate.AcquireLock(reason)의 토큰을 보유하고
UI 종료 시 Dispose한다. 중복 잠금은 모두 해제되어야 조작이 복귀한다.

## 설정과 씬 수정
Assets/_Project/HaJongUk/Assets/Settings/DefaultMovement.asset에서 속도·감도·시간 제한을 조정한다.
개인 씬에서 검증한 뒤 공용 씬에 반영한다. 지형 변경 시 개인 씬은 Auto Update 설정에 따라 자동으로, 공용 씬은 수동으로 NavMesh를 다시 베이크한다.
초기 생성 메뉴 OpenSourceTeam6/Movement/Create Initial Scenes는 기존 씬·프리팹을 덮어쓰지 않는다.
공용 씬도 HaJongUk의 프리팹·설정·재질을 참조하므로 해당 에셋을 함께 유지해야 한다.

## 확인 결과
- EditMode 9개 통과: 방향·속도·시점 제한·잠금·요청 교체·결과 큐 상한.
- PlayMode 7개 통과: 도착·단절 경로·취소·일시정지·비활성화·재진입 알림·카메라·벽 충돌·큰 시간 간격.
- 개인 및 공용 씬 각각 단독 실행하여 Arrived/None 확인.
- 초기 개인 씬의 분리된 섬은 Failed/PartialPath를 확인했다. 이후 바닥 확장과 NavMesh 재베이크 후 Target_3 도착을 확인했다.
- 공용 씬 카메라 1개, AudioListener 1개, 플레이어 Renderer 0개 확인.
- Windows 개발 빌드 결과는 아래 추가 기록을 따른다.

## 남은 검증
자동 속도 비교는 순수 계산 기준이다. 실제 장비의 30/60/120FPS 이동 거리·성능 비교,
다수 직원 혼잡도, 실제 마우스 조작감과 최종 아트 적용은 후속 검증한다.
일반 NPC 행동, 점프·달리기, 애니메이션, 음성·감정·스토리는 현재 구현 범위에 포함하지 않는다.

Windows 개발 빌드: 이전 구현에서 StandaloneWindows64 빌드 성공(오류 0, 경고 13). 이후 변경을 반영한 Windows 빌드 및 빌드 실행은 확인하지 않았다.

## 프리팹 컴포넌트 구조 변경
플레이어는 PlayerRigController 하나가 입력·잠금·이동·시점 보조 객체의 수명을 관리한다.
직원은 EmployeeMovementController 하나가 NavMeshAgentDriver 객체를 소유한다.
각 기능의 계산과 책임은 기존 클래스에 유지하며, Unity CharacterController와 NavMeshAgent는 계속 부착한다.
입력 에셋·눈 위치·카메라·MovementProfile은 PlayerRigController Inspector에서 설정한다.
직원 이동 공개 인터페이스와 PlayerRigController.InputGate는 유지한다.
기존 보조 클래스는 MonoBehaviour가 아니므로 GetComponent 또는 AddComponent로 사용할 수 없다.
변경 후 Unity PlayMode 통합 테스트 7개 통과, 개인 씬의 프리팹 인스턴스 구성 확인.

## 작업 씬 NavMesh 자동 갱신
개인 씬의 Environment_Navigation에서 NavMesh Auto Bake의 Auto Update를 켜면,
자식 콜라이더의 크기·위치·활성 상태 등이 바뀐 뒤 약 0.75초 후 NavMesh를 재생성한다.
끄면 개발자가 NavMeshSurface의 Bake를 직접 실행한다. 기존 NavMesh 에셋을 갱신하므로
해당 에셋의 변경을 저장소에 반영해야 다른 팀원에게 적용된다. 에디터 편집 중에만 동작하며,
Collect Objects=Children, Use Geometry=Physics Colliders 설정과 편집 가능한 NavMesh 에셋이 필요하다.

현재 개인 씬의 NavMesh는 Scenes/HJU_CameraMovement_Work/NavMesh-Environment_Navigation.asset이다.
자동 베이크는 에셋 GUID를 유지하며 복사 후 파일명과 에셋 이름을 일치시킨다.
Target_1·2는 이동 함수를 통해 각각 Arrived를 확인했으며 물리 키보드 입력은 별도 확인이 필요하다.

## 팀원용 공개 API와 수정 경계

### 직원 이동: 사용 가능한 API

`EmployeeMovementController`를 Inspector에 연결한 뒤 `IAgentMovement`로 사용한다.
사용 어셈블리가 asmdef를 사용한다면 `OpenSourceTeam6.Movement.Core`와
`OpenSourceTeam6.Movement.Unity`를 참조한다. 모든 호출과 결과 처리는 Unity 메인 스레드에서 한다.

| API | 용도와 주의사항 |
|---|---|
| `RequestMove(new WorldPoint(x, y, z))` | 월드 좌표(m) 목적지로 이동 요청. 반환값의 `Accepted`, `RequestId`, `RejectReason`을 확인한다. 수락은 도착 성공이 아니다. |
| `Cancel(requestId)` | 현재 진행 중인 같은 ID의 요청만 취소한다. 성공 여부를 bool로 반환한다. |
| `Snapshot` | 현재 `Position`, `ActualVelocity`, `State`, `ActiveRequestId`, `LastFailure`를 값으로 조회한다. |
| `Finished` | 수락된 요청이 도착·실패·취소로 종료되면 결과를 받는다. `RequestId`, `Status`, `Failure`, `Cancellation`, `FinalPosition`을 확인한다. |

`WorldPoint`의 좌표는 유한한 월드 좌표이며, 직원이 설 수 있는 바닥 근처를 전달한다.
거절된 요청은 종료 이벤트가 없다. 수락한 새 요청은 기존 요청을 `Replaced`로 취소한다.
유효하지 않은 새 목적지 또는 준비되지 않은 요청은 기존 이동을 유지한다.
정상적인 결과는 LateUpdate에서 전달되지만 직원이 비활성화될 때는 종료 결과가 OnDisable에서
즉시 전달될 수 있다. 수신자는 요청 ID를 비교하고 자신의 OnDisable에서 구독을 해제한다.
오래된 요청 ID는 다른 요청이나 다른 직원에게 재사용하지 않는다.

```csharp
using OpenSourceTeam6.Movement.Core;
using OpenSourceTeam6.Movement.Unity;
using UnityEngine;

public sealed class EmployeeMoveExample : MonoBehaviour
{
    [SerializeField] private EmployeeMovementController employee;
    [SerializeField] private Transform destination;
    private IAgentMovement movement;
    private long pendingId;

    private void OnEnable()
    {
        if (employee == null) return;
        movement = employee;
        movement.Finished += OnFinished;
    }

    public void BeginMove()
    {
        if (movement == null || destination == null) return;
        Vector3 p = destination.position;
        MoveReceipt receipt = movement.RequestMove(new WorldPoint(p.x, p.y, p.z));
        if (receipt.Accepted) pendingId = receipt.RequestId;
        else Debug.LogWarning($"이동 요청 거절: {receipt.RejectReason}");
    }

    private void OnFinished(MoveOutcome result)
    {
        if (result.RequestId != pendingId) return;
        pendingId = 0;
        if (result.Status == MoveState.Arrived)
            Debug.Log("목적지 도착: 담당 행동 시스템에서 다음 업무를 결정");
        else
            Debug.Log($"이동 종료: {result.Status}, {result.Failure}, {result.Cancellation}");
    }

    private void OnDisable()
    {
        if (movement == null) return;
        movement.Finished -= OnFinished;
        if (pendingId != 0) movement.Cancel(pendingId);
        pendingId = 0;
        movement = null;
    }
}
```

`Failed`의 예: `NoPath`·`PartialPath`·`PlanningTimeout`·`Stalled`·
`DeadlineExceeded`·`TargetUnavailable`. 취소는 `Requested`·`Replaced`·`Disabled`로 구분한다.
이동 실패 시 다음 업무, 재시도, 플레이어 안내는 호출한 행동 시스템이 결정한다.

### 플레이어: 사용 가능한 API

`PlayerRigController.InputGate`는 `IPlayerInputGate`를 제공한다. `Awake` 초기화 이후
참조를 얻고 null 여부를 확인한다. `AcquireLock("사유")`이 반환한 `IDisposable`을
보관해 UI가 닫힐 때 `Dispose()`한다. 여러 잠금 중 하나만 해제해도 나머지 잠금은 유지된다.
`IsLocked`로 잠금 상태를 조회하며 입력 잠금 중에도 중력은 적용된다.
`PlayerRigController.Look`의 `YawDegrees`, `PitchDegrees`는 현재 시점 조회용이다.

### 직접 수정하지 않는 영역

- `Assets/_Project/HaJongUk/Scripts/Camera/`, `Scripts/Movement/`의 내부 구현과 asmdef:
  다른 담당자가 수정할 필요가 있으면 담당자 하종욱에게 Issue로 요구 사항을 전달한다.
- 직원의 `NavMeshAgent` 위치·회전·경로를 외부 시스템에서 직접 변경하지 않는다.
  `IAgentMovement`로 요청해야 종료 결과와 상태가 일치한다.
- 플레이어의 `CharacterController` 이동, 루트 회전, `EyePivot` 회전을 다른 시스템에서
  동시에 쓰지 않는다. 별도 연출이나 카메라 제어가 필요하면 담당자와 소유권을 먼저 조율한다.
- `PlayerInputReader`, `PlayerInputGate`, `CharacterControllerMotor`,
  `FirstPersonCameraPresenter`, `NavMeshAgentDriver`는 현재 내부 보조 객체다.
  이름이 public이어도 팀 간 안정적인 연동 API로 취급하지 않고 `GetComponent`로 찾지 않는다.
- 프리팹의 구성·직렬화 참조, `.meta` GUID, 입력 에셋, 기본 MovementProfile,
  NavMesh 에셋을 변경하거나 이동하기 전 담당자와 영향 범위를 조율한다.
  Profile은 공유 에셋이므로 값을 바꾸면 참조 중인 모든 프리팹에 영향을 준다.
- 공용 씬에 자기 시스템을 추가할 수 있으나, 공용 씬 동시 수정과 프리팹 적용은
  담당자와 조율한다. 기존 설정이나 개인 씬을 임의로 덮어쓰지 않는다.

### 음성 인식 담당자 연결 순서

1. 음성 인식 및 명령 해석에서 대상 직원과 업무를 판별한다.
2. 행동 시스템에서 업무 위치를 결정하고 해당 직원의 `IAgentMovement`로 이동을 요청한다.
3. `Accepted`와 요청 ID를 저장하고, `Finished`에서 같은 ID의 결과를 확인한다.
4. 도착이면 업무 수행을 진행하고, 실패·취소면 행동 시스템에서 후속 처리를 결정한다.
5. 백그라운드 음성 처리 결과는 Unity 메인 스레드로 넘긴 뒤 직원의 유효성을 확인해 호출한다.
