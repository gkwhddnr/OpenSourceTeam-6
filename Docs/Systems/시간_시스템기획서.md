# 시간 시스템 기획서

담당: 하종욱 | 상태: 후속 구현 설계 | 대상: PC 싱글플레이

## 목적과 플레이 경험
플레이어는 영업 HUD의 일차·시각과 매장 밖의 낮·밤 변화를 보고 남은 영업 시간을 파악할 수 있어야 한다. 시간이 흐르면 조명과 하늘이 자연스럽게 변하고, 다음 일차를 시작하면 즉시 낮의 영업 시작 상태로 돌아가야 한다.

## 게임 흐름
로비 → 직원 채용 → 첫 화면의 POS·문서로 조작과 규칙 확인 → 영업 시작 → 낮에서 밤으로 진행 → 영업 종료 → 일차 정산 → 직원 상태 확인 → 다음 일차 준비 또는 엔딩.

영업은 목표 매출을 달성해도 시간 종료까지 계속된다. 조기 마감은 매출 목표와 분리된 정책이며, 직원 상태 등에 따른 조기 마감 조건은 UI·직원 담당자와 통합 시 확정한다.

## 요구사항
- 일차, 현재 시각, 진행률은 하나의 시간 값을 공유하며 HUD와 게임 공간에 동일하게 반영한다.
- 실제 하루 플레이 시간과 게임 속 개점·폐점 시각은 설정 가능하게 한다. 구체적인 수치는 플레이 검증 후 확정한다.
- 일시정지 중 시간과 NPC 시뮬레이션은 함께 멈춘다. 커서 잠금 해제만으로 시간을 멈추지는 않는다.
- 마감 시 신규 손님 입장을 중단하고 진행 중 거래를 정리한 후 일차 정산을 한 번만 실행한다.
- 정산 화면에서 다음 일차를 선택해야 일차가 증가한다. 엔딩 판정 이후에는 다음 일차를 시작하지 않는다.
- 다음 일차는 누적 자금과 직원 상태를 인계받되 시각·낮밤 진행률은 시작값으로 초기화한다.

## 담당 경계와 범위
하종욱은 시간 진행·낮밤 표현·마감 신호를 담당한다. 송재명은 HUD·정산·화면 전환을, 이승재는 직원 업무·감정 처리를 담당한다. 기존 UI 타이머가 존재하므로 시간을 중복 구현하지 않고 단일 기준으로 연결한다.

중간발표 범위는 영업 시작부터 시간 경과, 손님 구매, 시간 종료와 정산으로 이어지는 하루 루틴이다. 저장·불러오기, 계절과 실제 천문 시뮬레이션은 이번 최소 범위에 포함하지 않는다.

## 완료 기준
HUD 시각과 조명의 진행률이 일치하고, 일시정지·재개와 다음 날 초기화가 동작하며, 마감·정산이 일차당 한 번만 발생해야 한다.


## 낮·밤 표현 설계 (.Unity 지침 반영)
근거는 `.Unity/PROJECT_CONVENTION.md` 26장과 `.Unity/CELESTIAL_TIME.md`이다. 이 프로젝트는 영업 시간을 압축하는 게임 연출 모드를 사용한다. 실제 날짜·위도에 따른 천문 계산이나 계절 변화는 별도 확장으로 구분한다.

| 구간 | 플레이어에게 보이는 변화 | 유지할 조건 |
|---|---|---|
| 영업 시작·낮 | 밝은 하늘과 햇빛, 판독 가능한 실내 | HUD 시작 시각과 조명이 같은 시점으로 초기화 |
| 오후·해질녘 | 태양 방향, 빛 색과 밝기가 점진적으로 변화 | 그림자·하늘의 태양 방향 일치, 갑작스러운 색 전환 방지 |
| 저녁·밤 | 햇빛 감소, 어두운 하늘과 실내 조명 대비 | 상품·직원·통로와 HUD의 가독성 유지 |
| 다음 일차 | 즉시 시작 시각의 낮으로 복귀 | 이전 날의 조명·환경광·반사가 남지 않도록 갱신 |

태양의 직접광, 보이는 하늘, 주변 환경광, 물체의 반사는 서로 다른 표현 요소로 관리한다. 하늘 배경만 바꾸고 실내 조명이나 반사가 낮에 머무는 상태는 완료로 보지 않는다. 밤의 달 표시는 필수가 아니며, 추가하면 태양 반대편에 고정한 것을 실제 달 위치로 설명하지 않는다.

설치된 URP 패키지에 맞는 Skybox와 Directional Light 구성을 기본 후보로 삼되 실제 씬·품질 설정을 확인한 후 확정한다. 구름·안개는 현재 파이프라인에서 지원되는 범위로 제한한다. 낮밤 구현을 위해 HDRP로 변경하거나 체적 구름 패키지를 추가하지 않는다.

환경 변화는 매끄럽게 보이도록 하되 환경광·반사 재계산 주기는 화면 표현과 별도로 제한한다. 실내외, 해질녘, 밤, 다음 날, 일시정지와 재개를 실제 게임 화면에서 확인해야 한다.


## Issue #13 시간·커서 연동 요구사항
영업 종료 시각에 도달하면 현재 직원 스트레스를 정산에 전달하고 정산 화면으로 전환한다. 스트레스는 직원 시스템이 관리하는 최신 확정값을 사용하며 시간 시스템이 별도로 계산하지 않는다. 마감 정리 중 게임 시간이 더 진행하거나 정산이 중복 실행되지 않아야 한다.

Tab 명령창, Esc 일시정지, 설명서, 정산창을 열면 플레이어가 마우스로 UI를 조작할 수 있도록 카메라 회전을 중지하고 커서를 표시한다. UI를 닫을 때 다른 팝업이 남아 있으면 회전을 재개하지 않는다. 이때 커서/카메라 입력 잠금과 영업 시간의 일시정지는 구분한다. 시간 정지는 일시정지 화면 등 명시적인 정책에만 적용하며 설명서·명령창의 시간 정지 여부는 UI 담당자와 확정한다.

근거: [GitHub Issue #13](https://github.com/gkwhddnr/OpenSourceTeam-6/issues/13) (2026-11-15 확인).

## 비 날씨 확장 (2026-11-17)

`isRain`은 목표 날씨다. 켜면 12초 전환의 앞 6초에 구름이 하늘 전체를
덮고, 이후 6초에 빗줄기가 약한 비에서 강한 비로 증가한다. 끄면 빗줄기가
먼저 약해지고 멈춘 뒤 구름이 걷힌다. 도중에 다시 전환해도 현재 상태에서 이어진다.
밤에는 같은 구름을 어두운 색으로 표시한다. 비가 내리는 동안 거리 안개를 적용하며 안개 강도는 0~100%로 조절한다. 실제 강우량에 맞춰 서서히 나타나고 사라지며, 밤에는 더 어두운 색을 사용한다. 0%에서는 비로 인한 안개를 적용하지 않는다.

강우 범위는 맵 확정 전에는 카메라를 따라가며, 맵 확정 후에는 월드 좌표의 고정 영역을 설정할 수 있다. 영역 크기와 비의 밀도는 성능을 확인하며 조정하고, 건물과 지면의 충돌체를 이용해 실내를 가린다.

바닥·지붕의 정적 Collider에 닿은 비는 사라지며 일부 충돌에서 짧은 물튀김이
생긴다. 실제 물·웅덩이·움직이는 지붕은 이번 범위에 포함하지 않는다.
물튀김도 비와 함께 일시정지되고, 그칠 때 남은 입자는 자연스럽게 사라진다.
테스트 UI는 실시간 isRain 토글, 강우·구름 진행률과 빗방울·물튀김 수를 표시한다.
하종욱이 TIME-01의 시각 효과 확장으로 관리한다. 하늘 표현·입자 생성은
정산·직원 행동에 직접 영향을 주지 않는다.
