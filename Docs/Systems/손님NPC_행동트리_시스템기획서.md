# 손님 NPC 행동 트리 시스템 기획서

담당: 하종욱 | 상태: 후속 구현 설계

## 역할 구분
최근 회의 기준 하종욱 담당은 손님·행인 NPC이다. 음성 명령을 받는 직원 AI와 업무·감정 시스템은 이승재 담당이며, 이 문서는 직원 AI를 새로 구현하는 명세가 아니다. 직원에게 상품 위치를 묻거나 결제를 요청하는 연동 경계를 포함한다.

## 플레이 경험과 기본 루틴
플레이어가 직접 조작하지 않아도 손님은 편의점에 들어와 물건을 고르고 집은 뒤 계산대로 이동해 결제하고 매장을 나가야 한다. 매장 밖 행인은 별도의 경로를 따라 지나가 도시 환경의 움직임을 만든다.

기본 흐름: 입장 → 상품 선택·예약 → 진열대 이동 → 상품 집기 → 계산 대기 → 결제 확인 → 퇴장 → 외부 목표지점 이동 → 정리.

손님은 플레이어 또는 직원의 결제 처리를 기다릴 수 있어야 한다. 이동 도착만으로 상품 획득이나 결제 성공으로 처리하지 않는다. 재고 부족·경로 실패·대기 초과 시 무한 대기하지 않고 다른 상품을 선택하거나 구매를 취소하고 퇴장한다.

## 범위
중간발표는 손님 한 명의 구매·결제·퇴장과 시간 종료에 따른 마감 루틴을 우선 완성한다. 가벼운 임시 캐릭터와 도시 매장 배치로 검증한다. 다수 손님·질문·상품 요구·돌발 행동은 기본 루틴 이후 확장한다.

영업 종료 시 신규 손님을 생성하지 않는다. 진행 중 구매는 정해진 정리 정책에 따라 완료 또는 취소하고, 예약·대기열을 반환한다. 일시정지 중 손님 행동과 이동도 함께 정지한다.

## UnityHFSM 채택 결정
현재 범위에서는 UnityHFSM을 도입하지 않고 작은 행동 트리를 작성한다. 구매 순서를 순차 처리하면서 마감·취소를 우선 판단하는 구조가 필요하며, 별도 계층 상태 머신을 함께 유지할 필요가 적다. 직원 AI 담당자의 라이브러리 선택에는 적용하지 않는다. 복잡한 독립 모드가 추가되면 재검토한다.

## 완료 기준
손님이 자동으로 한 번 구매하고 퇴장하며, 결제가 중복되지 않고, 실패·마감·씬 종료 시 예약과 대기열이 남지 않아야 한다.


## Issue #13 손님·혼잡과 직원 시스템 연결
손님이 실제로 입장하면 출입문 알림음을 한 번 재생하고, 계산이 성공 확정되면 바코드 결제음을 한 번 재생한다. 결제 요청만 했거나 이동이 끝난 시점에는 결제음을 재생하지 않는다.

계산 대기열이 과다하거나 매장 안에서 소란이 발생하면 직원 시스템에 혼잡·소란 상태를 전달한다. 혼잡과 소란이 함께 있어도 추가 스트레스 요인은 한 번만 적용한다. 이슈 기준 지속 스트레스는 업무 중 초당 +1.2×업무 배율, 휴식·대기 중 -1.8×회복 배율이며, 혼잡·소란 중에는 초당 +0.8×업무 배율이 추가된다. 실제 스트레스 계산·범위 제한은 직원 상태 소유자가 수행한다.

대기열 과다의 인원 기준, 해제 기준, 소란 발생·종료 조건은 이슈에서 확정되지 않았으므로 설정 및 담당자 합의 대상으로 남긴다. 혼잡 해제와 모든 소란 종료 후 추가 요인을 해제한다. 질문·돌발 행동은 후속 확장 범위를 유지한다.
