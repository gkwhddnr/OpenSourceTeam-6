# 손님·행인 NPC 행동 트리 시스템 기획서

담당: 하종욱 | 상태: 구현 전 기획 · 갱신: 2026-11-19

## 기준 자료와 데모 범위 확인

기준 자료는 2026-11-07 팀 공유 마스터 흐름서, 최근 회의에서 정한 도시 배경·손님 동선, [Issue #13](https://github.com/gkwhddnr/OpenSourceTeam-6/issues/13), 그리고 이후 확정한 계산 대기 우선 범위다. 충돌하는 데모 범위는 **최근 회의를 기준**으로 한다. 따라서 11월 30일 중간발표에서 손님의 입장·상품 집기·계산·퇴장과 일차 마무리로 이어지는 하루 루틴을 보여주는 것이 목표다. 이전 마스터의 직원 외 NPC 보류·가상 매출만 사용하는 1차 데모 범위는 과거 계획으로 참고한다. 목표가 정해졌다는 사실은 기능 구현이나 검증이 완료되었다는 뜻은 아니다. 마스터의 120초 시연값과 현재 시간·UI 연동에서 사용하는 값은 동일하다고 단정하지 않는다.

마스터에는 목표 달성과 별도로 조기 마감 기능이 제안되어 있다. 현재 시간 시스템의 마감과 손님 정리 정책 및 UI 흐름은 확정되지 않았으므로 조기 마감의 도입 여부·동작·우선순위를 담당자와 확인한다. 목표 달성만으로 자동 종료하지 않는 기존 결정은 유지한다.

## 역할 구분
하종욱 담당은 편의점 손님과 도시 거리 행인 NPC이다. 음성 명령을 받는 직원의 업무·감정 시스템은 별도 팀원 담당이다. 손님과 행인은 감정·스트레스·직원 페르소나를 갖지 않는다. 손님은 혼잡 상태와 결제 요청을 직원 시스템과 연동한다. 상품 위치 질문은 도입 여부부터 확인해야 하는 후순위 항목이다.

## 플레이 경험과 기본 루틴
도시 배경의 편의점 밖에는 보도와 주변 건물이 배치된다. 손님은 보도를 통해 편의점으로 들어와 물건을 고르고 계산한 뒤 나가며, 행인은 매장에 들어가지 않고 보도를 따라 지나가 도시의 움직임을 표현한다. 보도·건물·출입구 위치와 동선은 맵 담당자와 협의한다.

| 역할 | 출현과 목표 | 매장 연동 |
| --- | --- | --- |
| 손님 | 외부 출현 지점 → 매장 입구 → 구매·결제 → 출구 → 외부 목표 지점 | 입장·상품·계산·혼잡 상태 연동 |
| 행인 | 보도 출현 지점 → 보도 경유 지점 → 다른 외부 목표 지점 | 구매·계산·매장 혼잡 집계 없음 |
| 직원 | 플레이어 지시에 따른 업무 수행 | 별도 팀원 시스템; NPC 감정 역할과 혼동하지 않음 |

출현 시 손님 또는 행인 역할을 부여한다는 것은 설계 제안이다. 두 역할 간 전환, 출현 비율·간격·동시 인원과 영업 종료 후 거리 연출은 아직 확정되지 않았다. 행인이 걸어간다고 모두 편의점 입장 대상은 아니다.

기본 흐름: 입장 → 상품 선택·예약 → 진열대 이동 → 상품 집기 → 계산 대기 → 결제 확인 → 퇴장 → 외부 목표지점 이동 → 정리.

손님은 플레이어 또는 직원의 결제 처리를 기다릴 수 있어야 한다. 이동 도착만으로 상품 획득이나 결제 성공으로 처리하지 않는다. 재고 부족·경로 실패는 다른 상품을 선택하거나 구매를 취소하고 퇴장하는 방식으로 처리한다. 대기 시간 초과에 따른 자발적 이탈은 추후 확장이다.

## 계산 대기와 추후 확장

우선 계산대마다 대기열을 관리한다. 앞 손님이 계산 중이면 뒤 손님은 순서대로 기다리며, 각 손님의 대기 경과 시간은 서로 독립적으로 측정하고 게임 화면에 표시한다. 표시 위치·형식과 여러 손님을 한 번에 보여주는 방식은 UI 담당자와 협의한다. 계산이 시작되면 해당 손님의 대기 시간 측정을 종료한다. 일시정지 중 대기 시간도 멈춘다.

**추후 확장:** 개인별 기본 대기 한도를 넘으면 직원과 플레이어에게 음성 또는 텍스트로 독촉하는 방안을 유지한다. 기본 대기 한도와 추가 대기 한도, 대사·음성 제작 및 출력 방식은 조율 대상이다. 독촉은 시간 조건에 따른 행동이며 손님용 감정·성격 수치를 도입하지 않는다.

**추후 확장:** 추가 시간까지 계산이 시작되지 못하면 구매를 취소하고 퇴장하며, 이탈 시 인지도 또는 평가가 감소하는 연동을 검토한다. 예약 반환과 미확정 매출 처리, 평가 종류·감소량·저장·책임은 추후 관련 담당자와 확정한다. 우선 구현에서는 대기 시간 경과만으로 독촉하거나 자동 이탈하지 않는다.

영업 마감과 결제 중 실패·중단에 대한 세부 정책은 UI·경제 담당자와 별도 합의한다.

## 범위
11월 30일 중간발표까지 손님 한 명의 입장→상품 집기→계산→퇴장→외부 목표 지점 이동과 시간 종료 후 정산으로 이어지는 하루 흐름을 우선 목표로 한다. 행인의 보도 이동도 별도 역할로 설계하며 시연 포함 여부와 구현 시기는 팀 일정에 따라 조율한다. 도시 배경과 가벼운 임시 캐릭터·도구로 검증하며 맵의 최종 치수·상품 배치는 담당자 협의 후 확정한다. 다수 손님은 기본 루틴 이후 확장한다.

| 구분 | 행동 | 결정 상태 |
| --- | --- | --- |
| 기본 | 입장, 상품 위치로 이동·집기, 계산대로 이동·결제, 퇴장 후 외부 목표 이동 | 중간발표 목표 |
| 계산 대기 | 순서 유지, 손님별 대기 경과 시간 측정·표시 | 우선 구현; UI 표시 방식 협의 |
| 독촉·이탈·매장 평가 | 한도 초과 독촉, 추가 시간 후 취소·퇴장, 인지도 또는 평가 감소 | 추후 확장; 시점·수치·연동 방식 미정 |
| 거리 연출 | 행인이 편의점 밖 보도를 따라 외부 목표까지 이동 | 추가 설계; 시연 포함 여부·구현 일정 협의 |
| 추가 | 매장 내 소란 | 추가 행동으로 검토; 발생·종료 조건과 처리 방식 미정 |
| 후순위 | 상품 위치 질문 | 추가 여부 미정; 결정되더라도 중간발표 이후 우선순위 |

아래의 예약·대기열·시간 제한과 마감 정리는 구현을 위한 제안이며, 실제 재고·결제·UI 담당자와의 계약 및 수치 합의가 필요하다. 목표를 채워도 영업시간이 끝나기 전에는 하루를 종료하지 않는다.

마스터 흐름서의 본편 후보에는 상품 선택과 품절 시 매출 기회 손실, 직원 계산과 플레이어 직접 계산, 직원 건당 수당 및 플레이어 직접 계산의 속도·직원 상태 영향이 포함된다. 이는 경제·직원 시스템과 합의가 필요한 **본편 연동 후보**이며 손님 트리가 수당·직원 감정·매출을 직접 계산하지 않는다. 진상 이벤트, 날씨별 수요·오염 및 일차별 해금도 후속 후보로 둔다.

영업 종료 시 신규 손님을 생성하지 않는다. 진행 중 구매는 정해진 정리 정책에 따라 완료 또는 취소하고, 예약·대기열을 반환한다. 일시정지 중 손님 행동과 이동도 함께 정지한다.

## UnityHFSM 채택 결정
현재 범위에서는 UnityHFSM을 도입하지 않고 작은 행동 트리를 작성한다. 구매 순서를 순차 처리하면서 마감·취소를 우선 판단하는 구조가 필요하며, 별도 계층 상태 머신을 함께 유지할 필요가 적다. 직원 AI 담당자의 라이브러리 선택에는 적용하지 않는다. 복잡한 독립 모드가 추가되면 재검토한다.

## 완료 기준
손님이 자동으로 한 번 구매하고 퇴장해 외부 목표에 도착해야 한다. 행인 기능을 구현할 때는 매장에 들어가지 않고 지정된 보도를 지나 외부 목표에 도착해야 한다. 결제는 중복되지 않아야 하며, 실패·마감·씬 종료 시 사용 중인 예약과 대기열이 남지 않아야 한다. 시간 종료와 정산 사이 거래 정리 방식은 담당자 합의 후 통합 검증한다.


## Issue #13 손님·혼잡과 직원 시스템 연결
손님이 실제로 입장하면 출입문 알림음을 한 번 재생하고, 계산이 성공 확정되면 바코드 결제음을 한 번 재생한다. 결제 요청만 했거나 이동이 끝난 시점에는 결제음을 재생하지 않는다.

계산 대기열이 과다하거나 매장 안에서 소란이 발생하면 직원 시스템에 혼잡·소란 상태를 전달한다. 혼잡과 소란이 함께 있어도 추가 스트레스 요인은 한 번만 적용한다. 이슈 기준 지속 스트레스는 업무 중 초당 +1.2×업무 배율, 휴식·대기 중 -1.8×회복 배율이며, 혼잡·소란 중에는 초당 +0.8×업무 배율이 추가된다. 실제 스트레스 계산·범위 제한은 직원 상태 소유자가 수행한다.

대기열 과다의 인원 기준, 해제 기준, 소란 발생·종료 조건은 이슈에서 확정되지 않았으므로 설정 및 담당자 합의 대상으로 남긴다. 혼잡 해제와 모든 소란 종료 후 추가 요인을 해제한다. 질문·돌발 행동은 후속 확장 범위를 유지한다.
