# 시간 시스템 개발서

담당: 하종욱 | 상태: 구현 전 설계 (아래 타입과 API는 제안)

## 구조
`OpenSourceTeam6.Time.Core`는 Unity 비의존 시간 규칙과 상태를 관리하고, `.Unity`는 기존 UI 타이머 및 조명에 연결한다. 기존 `StoreUiSessionController`의 타이머 소유권을 먼저 확인하여 기존 타이머를 어댑터로 사용하거나 시간 코어에 위임한다. 두 타이머가 각각 증가하는 구조는 허용하지 않는다.

## 제안 계약
- `BusinessTimeSnapshot`: DayId, 단계, 경과 시간, 하루 진행률, 게임 시각.
- `IBusinessClock`: 스냅샷 조회와 변경 알림. 외부 UI는 읽기만 수행한다.
- `BusinessSessionCoordinator`: 일차 시작, 마감 요청, 다음 일차 전환을 조율한다.
- `ExistingTimerAdapter`: 기존 타이머와 시간 계약을 연결한다.
- `DayNightPresenter`: 동일 진행률에서 광원 방향·색·세기와 환경광을 계산한다.

시간은 double 경과값으로 누적하고 진행률을 0~1로 제한한다. 조명은 누적 회전 대신 진행률에서 매번 계산한다. 현실 천문 정확도는 요구하지 않으며 영업 체험에 맞는 곡선을 사용한다.

## 상태와 수명
Ready → Open → Closing → Settled → Ready 또는 Ended. 마감 요청은 DayId별 한 번만 수락한다. Closing에서는 신규 입장을 막고 NPC 거래 종료를 기다리되 유한한 제한시간 후 취소·자원 반환 정책을 적용한다. 이전 일차의 늦은 콜백은 DayId를 비교해 무시한다. 정산 확정과 다음 일차 시작은 각각 한 번만 처리한다.

일시정지는 소유자별 토큰으로 관리하고 모든 토큰 반환 후 재개한다. 시간과 NPC가 같은 정지 상태를 구독한다. 입력 잠금과 시뮬레이션 정지는 별도 책임이다. 씬 종료 시 구독과 토큰을 해제한다.

## 구현 순서
1. 기존 UI 타이머·정산 API를 확인하고 시간 소유권을 확정한다.
2. 시간 코어·설정·스냅샷과 시작/마감 규칙을 작성한다.
3. HUD 및 낮밤 표현을 연결한다.
4. NPC 마감 처리와 정산을 연결한다.
5. 다음 날과 종료 상태를 연결한다.

## 검증 계획
경계시간 초과, 중복 마감, 중첩 일시정지, 다음 날 낮 초기화, 이전 DayId 콜백, 씬 종료를 확인한다. 같은 일차에서 정산이 두 번 기록되지 않는지 확인한다. 이 문서 작성 시 구현 및 테스트는 수행하지 않았다.


## 낮·밤 구현 계약 (.Unity 지침 반영)
문서 확인 시 `ProjectVersion.txt`는 Unity 6000.6.4f1, manifest는 URP 17.6.0이다. 이는 패키지 선언 확인이며 실제 활성 렌더러·품질별 파이프라인·씬 조명은 구현 전에 조사한다. 지침: `.Unity/PROJECT_CONVENTION.md` 26장, `.Unity/CELESTIAL_TIME.md` 7~9장. 외부 API 문서는 구현 시 설치 버전에 맞춰 재확인한다.

### 계산·표현·소유권
- `BusinessTimeSnapshot`을 유일한 시간 입력으로 사용한다. HUD의 반올림된 문자열을 다시 파싱하거나 컴퓨터 현재 시각으로 낮밤을 독립 진행하지 않는다.
- 제안 `DayNightSettings`는 하루 구간, 태양 경로, 광량 곡선과 색 Gradient, 하늘·환경광 설정을 보관하는 읽기 전용 정의이다. NPC나 UI는 설정을 직접 변경하지 않는다.
- 순수 계산은 진행률에서 태양 방향·색·광량을 산출한다. `DayNightPresenter` 한 곳이 메인 스레드에서 광원·하늘·환경 표현을 적용한다. 동일 Light·RenderSettings를 다른 시스템이 동시에 쓰지 않도록 기존 소유자를 확인한다.
- 경과 시간·게임 시각은 double로 유지하고 렌더링 경계에서 변환한다. NaN·무한대·0 이하 하루 길이·누락된 참조를 검증하며 오류는 진단 가능한 상태로 처리한다.

### 광원과 하늘 연결
Directional Light는 위치 이동 대신 회전으로 방향을 표현한다. 장면의 북쪽과 위쪽 축을 명시하고, 태양을 향한 방향과 광선이 진행하는 방향의 부호를 구분해 그림자로 확인한다. 방향이나 Quaternion을 보간하며 359도에서 1도로 넘어가는 각도를 단순 보간하지 않는다. 수직 방향 근처에는 안전한 기준축을 사용한다.

Skybox Material·카메라 배경·Sun Source와 셰이더의 태양 표현 지원을 확인한다. 정적 하늘 텍스처는 광원 회전만으로 태양 그림이 움직이지 않으므로 선택한 하늘 방식과 일치시킨다. 직접광과 별도로 환경광의 Skybox/Gradient/Color 방식 및 반사·프로브를 조사한다. 움직이는 태양이 베이크된 간접광까지 갱신한다고 가정하지 않는다. 매장 실내 조명의 소유권은 맵 담당자와 조율한다.

공유 Skybox Material·Volume Profile은 런타임에 원본을 수정하지 않는다. 필요한 인스턴스를 수명당 한 번 만들고 씬 종료 시 원본 참조를 복구하고 소유 인스턴스를 해제한다. 매 프레임 머티리얼을 생성하거나 씬 전체를 검색하지 않는다. 추가 달 광원은 URP의 실제 추가 광원·그림자 지원과 비용을 확인한 후 도입한다.

### 갱신·점프·종료
가시 광원의 방향과 색 적용은 활성 영업 중 필요한 주기로 실행한다. 환경광과 반사 갱신은 의미 있는 진행률 변화·구간 전환에 따라 별도 제한하며, 구체 주기는 가속 시간과 허용 시각 오차 및 측정 비용을 기준으로 확정한다. `DynamicGI.UpdateEnvironment`와 프로브 캡처를 매 프레임 호출하지 않는다. 해당 API를 전체 베이크 갱신으로 취급하지 않는다.

다음 일차·시각 점프에서는 새 스냅샷을 즉시 적용하고 환경 갱신을 요청한다. 비동기 결과에는 DayId와 세대를 붙여 이전 날·이전 씬 결과가 덮어쓰지 않게 한다. 일시정지에서는 게임 시각 기반 연출도 정지한다. 비활성·씬 종료 시 예약 작업·구독을 정리하고, 파괴된 Unity 객체를 재검증한다.

### 천문 모드 확장 경계
현재 게임 연출 모드는 천문 정확도를 주장하지 않는다. 향후 실제 태양·달 기능이 요구되면 UTC 날짜·시각, 위도·경도, 좌표계·단위·정밀도·유효 날짜 범위를 명시한 독립 계산기를 추가한다. 태양과 달을 독립 계산하고 달을 태양의 반대 방향으로 고정하지 않는다. 계절 날씨·지형·식생 변경은 시간 계산과 별도 시스템으로 연결한다.

### 추가 검증과 완료 증거
낮·일몰·밤·다음 날을 동일 노출과 카메라로 비교한 뒤 의도한 자동 노출에서도 확인한다. 실내외 가독성, 그림자 방향, 하늘 태양 정합성, 환경광·반사 잔상, 일시정지·시각 점프, 씬 전환과 반복 실행, 저장 후 재개방을 점검한다. 환경 갱신 전후 CPU/GPU 비용과 가속 시간의 끊김을 측정하고 실제 렌더러·품질·해상도·갱신 주기를 기록한다. 문서 수정만 수행했으며 런타임 동작과 성능은 아직 검증하지 않았다.


## Issue #13 정산·카메라 계약과 현재 코드 차이
- 이슈의 정산 진입점은 `uiController.CompleteDayAndShowSettlement(currentStress)`이며 반환형은 로컬 계약에서 `DaySettlementResult`로 확인했다. `currentStress`는 최신 직원 스냅샷에서 전달하고, 직원이 아직 준비되지 않았을 때 0을 임의로 사용하지 않는다. 시작 전 의존성을 검증한다.
- 로컬 `StoreUiSessionController.Update`는 현재 자체 `remainingDaySeconds`를 감소시키며 종료 시 직접 정산을 호출한다. 구현 시 이 경로를 공통 시간 소유자에게 위임하거나 기존 타이머를 권위 시간으로 연결해야 한다. 두 종료 경로를 동시에 가동하지 않는다.
- 로컬 `CompleteDayAndShowSettlement`는 `SettleOnce` 후 정산 UI를 표시한다. 시간 코디네이터에서도 DayId별 호출을 제한한다. 손님 정리·결제 확정 후 최종 스트레스와 자금을 동결하고 호출하며, 정리 제한시간을 넘긴 거래는 취소한다. 이슈의 종료 시각 호출과 거래 정리 순서에 대해서는 UI 담당자와 연결 시 합의한다.

커서 계약은 UI의 `ICursorLockGate.IsLocked`이다. 여기서 true는 UI가 입력 잠금을 보유한다는 뜻이며 OS 커서가 숨겨진 상태를 뜻하지 않는다. UI 잠금 게이트와 기존 PlayerRig 입력 게이트를 어댑터로 연결한다. UI가 팝업 수명에 맞춰 토큰을 획득·반환하고 카메라는 잠금 중 Look 입력을 적용하지 않으며 커서는 표시·해제한다. 다른 팝업의 토큰이 남으면 잠금을 유지한다. 시간·NPC는 커서 잠금값을 일시정지 신호로 재사용하지 않는다.

추가 검증: 종료 프레임의 스트레스 전달, 기존 타이머와 중복 정산 방지, Tab/Esc/설명서/정산의 커서 표시, 중첩 팝업 닫기, 씬 종료 후 토큰 정리, UI 조작 중 카메라 회전 방지. 실제 런타임 검증은 구현 후 수행한다.
