## 1. 1차 통합 데모의 목적과 범위

본 문서는 개별 브랜치에서 구현된 **① UI·정산(`송재명`)**, **② 음성 인식·AI 판단(`이승재`)**, **③ 1인칭 이동·경로 탐색(`하종욱`)** 세 모듈을 하나의 공용 씬(`Team_Integration.unity`)으로 합치기 위한 **공통 규격과 데모 범위**를 정의한다.

### 1.1 데모 핵심 검증 흐름 (1 Day Vertical Slice)
```text
[게임 시작 화면(로비)]
   ──▶ [매장 진입: 플레이어(1인칭) + 알바 NPC 1명 스폰, 1일차 타이머 시작]
   ──▶ [플레이어가 음성(또는 Tab 텍스트)으로 알바에게 업무 오더]
   ──▶ [STT 인식 + LLM·감정 가중치로 알바의 '반응(수락/불만/거부/태만)' 판정]
   ──▶ [판정 결과에 따른 알바 대사·배너 출력 + 감정(스트레스·피로·충성도) 실시간 변화 + 구역 기본 이동]
   ──▶ [영업 제한 시간 종료 → 1일차 수익 정산 및 결과 등급 화면]
```

### 1.2 포함 범위 vs 후속(2차) 개발 이관 범위
| 구분 | 1차 통합 데모 포함 (이번 목표) | 데모 제외 · 후속 개발 이관 (Later) |
| :--- | :--- | :--- |
| **핵심 판정** | 음성/텍스트 오더 인식, AI 반응 코드 판정, 스트레스 구간별 반응 분기 | 세부 사고/이상행동 다종 분기 (물건 파손, 계산 착오 등) |
| **행동 표현** | 반응 배너·한 줄 대사 출력 + 지정 구역 마커(`카운터`/`진열대`/`대기석`)까지 기본 이동 | 물건 집기·진열 모션, 손님 응대 연출, 오브젝트 물리 상호작용 |
| **감정 시스템** | 업무 수행 시 스트레스·피로 상승, 대기/휴식 시 회복, 거부 시 분노 카운트 누적 | 아이템(간식/보너스) 케어, 캐릭터별 고유 트라우마·스토리 이벤트 |
| **정산 및 진행** | 1일차(`Day 1`) 실시간 예상 잔액 표시 및 종료 후 정산 결과창(3등급) | 다중 일차(`Day 2~7`) 세이브, 발주·고용 상점, 다수 알바(2인 이상) |

## 2. 매장 도메인 및 명령 · 반응 코드 통일 규격

기존 브랜치 간 업종 차이(편의점 vs 식당)를 해소하기 위해 **1차 데모의 무대는 '편의점'**으로 통일하며, 아래 열거형(코드)을 세 시스템의 공통 기준으로 사용한다.

### 2.1 플레이어 명령 의도 (`CommandIntent` — 5종)
| 의도 코드 | 한국어 발화 예시 | 매핑 업무 (`StaffWorkRole`) | 이동 목적지 마커 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| `CHECKOUT` | "계산대 봐줘", "카운터 지켜", "결제 좀 해" | `Checkout` (계산) | `Target_Counter` | 초당 계산 매출 발생 |
| `RESTOCK` | "진열대 채워줘", "물건 정리해", "재고 보충해" | `Restock` (진열) | `Target_Shelf` | 초당 진열 매출 + 최소 진열 시간 충족 |
| `REST` | "잠깐 쉬어", "대기해", "일 그만하고 쉬어" | `Idle` (휴식/대기) | `Target_Rest` | 매출 0원, 스트레스·피로 회복 |
| `CLARIFY` | "저기 그거 좀 해", "빨리 해봐" (대상 불명확) | 변경 없음 | 이동 없음 | ① 단순 인식 실패 배너 (`RecognitionFailed`) |
| `UNSUPPORTED` | "요리해 줘", "배달 다녀와" (편의점 외 업무) | 변경 없음 | 이동 없음 | ① 미지원 명령 배너 (`RecognitionFailed`) |

### 2.2 알바 AI 반응 코드 (`EmployeeReaction` — 데모 4종 + 후속 확장 예약)
명령 의도가 유효(`CHECKOUT`, `RESTOCK`, `REST`)할 때, AI 및 감정 가중치 시스템은 아래 반응 중 하나를 최종 반환한다.

| 구분 | 반응 코드 | 판정 의미 | UI 피드백 종류 | 업무 · 이동 처리 |
| :--- | :--- | :--- | :--- | :--- |
| **데모 적용** | `ACCEPT_NORMAL` | 성실하게 지시 수락 | `Accepted` (초록) | 요청 구역으로 이동 → 도착 후 업무 수행 |
| **데모 적용** | `ACCEPT_COMPLAIN` | 불만을 표출하지만 수락 | `Accepted` (초록, 불만 대사) | 요청 구역으로 이동 → 감소된 감정 효율(`0.8x`)로 수행 |
| **데모 적용** | `SLACK_OFF` | 지시를 흘려듣고 농땡이 | `RefusedByEmotion` (빨강) | `Idle` 전환 (`Target_Rest` 또는 제자리 대기), 매출 미발생 |
| **데모 적용** | `REFUSE_EMOTION` | 스트레스 임계로 정면 거부 | `RefusedByEmotion` (빨강) | 지시 무시(제자리), `RecordAngerRefusal()` +1 누적 |
| *후속 예약* | *`MISTAKE_DROP`* | *물건 떨어뜨림 / 진열 실수* | *2차 개발 예정* | *2차 개발 시 이상행동 연출 및 원가 손실 반영* |
| *후속 예약* | *`MISTAKE_CHECKOUT`* | *바코드 오결제 실수* | *2차 개발 예정* | *2차 개발 시 매출 차감 및 손님 불만 연출* |

> **참고**: 플레이어가 `REST`(휴식)를 지시한 경우에는 분노 상태여도 거부하지 않고 즉시 `ACCEPT_NORMAL`(휴식 전환)로 처리해 플레이어가 직원의 스트레스를 관리할 수 있는 탈출구를 보장한다.

## 3. 스트레스 구간별 반응 확률 설계 및 대사 기준

`OpenSourceTeam6.UI.Core.StressRules`의 3단계 스트레스 구간과 AI 행동 가중치를 아래와 같이 연동한다.  
*(1차 데모에서는 기본 확률 + 캐릭터 성격 보정 + LLM 제안 가중치 `1.25x` 방식으로 판정하며, 후속 개발 시 이상행동(`MISTAKE_*`) 비율을 아래 표에서 분할 확장한다.)*

### 3.1 스트레스 구간별 기본 반응 비율 (`CHECKOUT` / `RESTOCK` 지시 시)
| 스트레스 구간 | 상태 명칭 | 정산 작업 효율 | 정상 수락 (`ACCEPT_NORMAL`) | 불만 수락 (`ACCEPT_COMPLAIN`) | 태만/농땡이 (`SLACK_OFF`) | 정면 거부 (`REFUSE_EMOTION`) | 후속 이상행동 확장 메모 |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **`0 ~ 39`** | 안정 (초록) | **`1.0x`** | **88%** | 10% | 2% | 0% | 실수 거의 없음 (성격 `고지식함/게으름` 높을 때만 소폭 발생) |
| **`40 ~ 79`** | 피로·불만 (노랑) | **`0.8x`** | **30%** | **50%** | 12% | 8% | 2차 개발 시 불만 수락 중 약 15~20%를 `실수(MISTAKE)`로 분기 |
| **`80 ~ 100`** | 분노·임계 (빨강) | **`0.5x`** | **5%** | 15% | 25% | **55%** | 2차 개발 시 정면 거부 외 `대형 사고/이탈` 연출 추가 |

- **성격 스탯 보정 방향 (`0 ~ 100`)**:
  - `diligence`(성실함) 높음 → `ACCEPT_NORMAL` 가중치 상승
  - `laziness`(게으름) 및 `fatigue`(피로도) 높음 → `SLACK_OFF` 가중치 상승
  - `loyalty`(충성도) 낮음 → 고스트레스 구간에서 `REFUSE_EMOTION` 가중치 상승

### 3.2 반응별 HUD 배너 대사 예시 (행동 연출 대체용 시각 피드백)
별도의 캐릭터 감정 애니메이션이 없는 1차 데모에서도 AI 반응이 생생하게 전달되도록, 하단 배너에 **알바의 대사 문구**를 함께 표시한다.

- **`ACCEPT_NORMAL`**: `"네! 바로 계산대 보겠습니다."` / `"알겠습니다, 진열대 채워 둘게요."`
- **`ACCEPT_COMPLAIN`**: `"하... 조금 피곤한데 일단 가볼게요."` / `"방금도 일했는데... 알겠어요, 한다고요."`
- **`SLACK_OFF`**: `"아 몰라요, 다리 아파서 잠깐 쉴래요..."` *(업무 미수행 · 대기 전환)*
- **`REFUSE_EMOTION`**: `"지금 너무 힘들어서 못 하겠어요! 시키지 마세요!"` *(분노 거부 횟수 +1)*
- **`REST` 수락 시**: `"휴, 살았다... 잠깐만 숨 좀 돌릴게요."` *(스트레스·피로 회복 시작)*

## 4. 데모 시연용 수치 밸런스 (약 2분 시연 기준)

발표 및 데모 시연 시간(약 **120초**) 동안 **안정 → 불만 → 분노 거부 → 휴식 회복 → 1일차 정산** 전 과정을 자연스럽게 보여주기 위한 권장 설정값이다. (모든 수치는 Inspector에서 조정 가능하게 유지한다.)

### 4.1 시간 및 감정 증감 수치
| 항목 | 데모 권장값 | 설정 의도 |
| :--- | :--- | :--- |
| **1일차 영업 시간 (`DayDurationSeconds`)** | **`120초`** (2분) | 지루하지 않게 1일차 완주 및 정산까지 확인 가능한 길이 |
| **초기 스탯 (`시작 시`)** | 스트레스 `25` / 피로도 `15` / 충성도 `70` | 초반 15초는 안정(`초록`), 이후 빠르게 불만(`노랑`) 진입 가능 |
| **업무 수행 중 변화 (`Checkout` / `Restock`)** | 스트레스 **`+1.2 / 초`**, 피로도 **`+0.8 / 초`** | 약 15초 근무 시 불만(`40`), 약 45초 연속 혹사 시 분노(`80`) 도달 |
| **업무 중 타 업무 급변경 패널티** | 스트레스 즉시 **`+12`** | 일하는 도중 자꾸 다른 지시를 내리면 빠르게 스트레스 폭발 |
| **대기 · 휴식 중 변화 (`Idle` / `REST`)** | 스트레스 **`-1.8 / 초`**, 피로도 **`-1.0 / 초`** | 약 15~20초 쉬게 해주면 분노에서 불만/안정 구간으로 복구 가능 |
| **감정 거부/태만 발생 시 변화** | 충성도 **`-5`**, 거부 횟수 **`+1`** | 무리한 지시 반복 시 정산 등급 하락(`불안정 성공`) 유발 |

### 4.2 1일차 정산 밸런스 (`120초` 영업 기준 보정값)
- **기초 자금**: `50,000원`
- **초당 기준 매출**: 계산(`Checkout`) **`1,000원 / 유효초`**, 진열(`Restock`) **`650원 / 유효초`**
- **진열 최소 기준 시간**: 유효 진열 **`15초`** 미만 시 총 매출 `-20%`(`0.8x`) 패널티
- **비용 차감**: 상품 원가 `매출의 30%` + 일일 고정 운영비 `20,000원`
- **목표 잔액 (`TargetBalanceWon`)**: **`80,000원`**
  - 계산과 진열을 적절히 분배하고 스트레스를 관리하면 약 `82,000 ~ 95,000원`(`안정 운영 성공`) 달성 가능.

## 5. 인게임 조작키 및 시연 안전장치

| 입력 키 | 동작 | 비고 |
| :--- | :--- | :--- |
| `W` `A` `S` `D` + `마우스` | 플레이어 1인칭 이동 및 시점 회전 | UI 창이 열려 있지 않을 때만 동작 |
| **`V` 키** | **음성 녹음 시작 / 종료 토글** | 누르면 `듣는 중...`, 다시 누르면(또는 최대 시간 도달 시) `AI 판단 중...` 전환 |
| **`Tab` 키** | 보조 텍스트 명령창 열기 / 닫기 | 마이크 인식 오류 또는 시연장 소음 발생 시 즉시 텍스트로 동일 명령 전달 |
| **`Esc` 키** | 보조 창 닫기 / 마우스 커서 잠금 해제 | |
| **`F5` 키** *(데모 치트)* | 알바 스트레스 즉시 `+25` 증가 | 발표 중 시간 부족 시 불만/분노 반응을 즉시 시연하기 위한 안전장치 |
| **`F6` 키** *(데모 치트)* | 즉시 1일차 영업 종료 및 정산 진입 | 발표 시간 조절용 즉시 정산 단축키 |
