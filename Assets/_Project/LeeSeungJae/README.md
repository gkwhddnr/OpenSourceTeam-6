# 직원 음성 명령 데모

## 팀 기능 통합 테스트

`Scenes/VoiceIntegrationTest.unity`는 `Shared/Scenes/Team_Integration.unity`의 개인 복사본이다. 팀원의 직원·플레이어 프리팹과 공용 NavMesh를 원래 위치에서 참조하며, 원본 씬과 프리팹은 수정하지 않는다. 이 테스트 씬에서 기존 이동 데모 패널은 꺼두고 UI 프리팹과 입력 이벤트 시스템을 실행 중 생성한다. 원본 NavMesh를 다시 베이크하지 않는다.

1. Unity에서 `VoiceIntegrationTest.unity`를 열어 Play하고 로비의 게임 시작을 누른다.
2. `Tab`으로 텍스트 명령창을 열고 `민수야 진열해줘`, `진열 좀 해줘`, `진열대에 물건 채워줘`, `선반이 비었으니 채워놔` 또는 `재고 채워줘`를 입력한다. Qwen이 진열·이동·취소·불명확·미지원 중 명령을 분류한다. 직원 한 명인 데모에서는 이름을 생략할 수 있다.
3. 또는 인게임 화면에서 `R`을 누른 채 말하고 키를 놓으면 음성을 인식한다. 최대 녹음 시간은 55초다. 텍스트 명령창이 열려 있는 동안에는 새 녹음을 시작하지 않는다. 음성 입력에는 Inspector에 연결된 Whisper 모델이 필요하다.
4. 준비된 Qwen3.5-2B가 진열 명령과 직원 반응을 판단한다. 직원은 진열 업무 테스트 목적지 `Target_2`로 이동하거나 성격과 상태에 따라 무시·불평·휴식을 선택한다. 이어서 직원 성격·감정과 확정된 행동을 Qwen에 전달해 짧은 한국어 대사를 생성하고 UI와 Console에 표시한다. 대사 생성에 실패하면 행동별 기본 대사를 표시한다. 이동 도착, 실패, 취소도 표시된다.

### 지정 위치 이동과 중지

게임 화면에서 바닥을 화면 중앙에 조준하고 왼쪽 클릭한다. 위치 지정 안내가 나온 뒤 `R`을 누른 채 `저기로 가`, `절로 가`, `이동해`, `가`, `가줘` 등으로 말하면 직원이 클릭한 지점으로 이동한다. 클릭한 위치는 발화를 시작할 때 확정된다. UI가 열려 있거나 커서를 다시 잠그는 클릭은 위치 지정으로 사용하지 않는다. 유효하지 않은 지점을 클릭하면 이전 위치도 지워지며 다시 바닥을 지정해야 한다.

`그만해`, `멈춰`, `취소해`, `하지 마`, `가지 마`, `진열하지 마` 등은 진행 중인 이동이나 업무 판단을 취소한다. AI 판단 중에도 새 음성을 녹음해 취소할 수 있다. 음성 인식이 이미 진행 중일 때는 그 인식이 끝난 뒤 새 녹음이 가능하다. 직원 이동·취소는 기존 이동 시스템을 사용하며 실제 마이크, 클릭, 경로 및 동시 취소는 Unity에서 확인해야 한다.

Qwen의 구조화된 분류 결과를 실제 명령 분기에 사용한다. 자주 쓰는 명확한 취소 표현은 AI 판단 중에도 즉시 처리한다. 부정이 포함된 복합 지시나 `저것 좀 해`와 같이 대상 업무가 불명확한 요청은 나누어 다시 말하도록 안내한다. 특정 진열대 대상의 모델 분류가 `SPECIFIC`이면 아직 연결된 실제 진열대가 없어 실행하지 않는다. 모델이 직원 이름·대상이나 의도를 잘못 분류할 수 있으며, 현재는 직원 한 명과 임시 진열 목적지만 있다. 진열 분류의 실제 목적지는 항상 `Target_2`이므로 개별 상품·선반으로 구분되지 않는다. 인식 문장과 `[VoiceIntegration] 명령 해석` 로그를 확인한다.

`Target_2`는 이동 연동을 위한 임시 목적지이며, 실제 재고 변경·업무 애니메이션·실수 오브젝트 처리는 연결되지 않았다. UI 시뮬레이션 드라이버는 사용하지 않고, 실제 매출 정산 작업 샘플도 임의로 생성하지 않는다. 음성 모델과 Qwen 모델이 준비되지 않았다면 해당 기능은 오류를 표시한다. 생성 대사는 글자 수·한국어 포함 여부 등 형식만 검사하며 행동과 의미가 일치하는지는 실제 결과를 확인해야 한다. 세 단계 LLM 처리와 Unity 씬·마이크의 전체 동작은 에디터에서 확인해야 한다.

통합 씬의 모델은 `Assets/Qwen3.5-2B-Q4_K_M.gguf`이다. 기존 Qwen2.5 파일은 비교를 위해 유지한다. 다른 모델을 시험하려면 `Voice Movement Integration` 컴포넌트의 `Llm Model Path`를 변경한다. 빌드에서는 아래 플레이어 모델 폴더에 현재 씬의 모델과 동일한 파일명이 있어야 한다.

인식 문장이 틀리면 Unity Console의 `[VoiceIntegration] 녹음 진단`에서 녹음 시간(`duration`)과 신호 크기(`rms`, `peak`)를, `[VoiceIntegration] Recognized`에서 Whisper가 실제 변환한 문장을 확인한다. 음성 변환과 이후 업무 해석은 별도 단계다. `rms`와 `peak`가 0에 가깝다면 마이크 선택·입력 음량을 확인한다. 입력 장치는 Console에 표시되며, `Voice Movement Integration`의 `Microphone Device Name`에 목록의 이름을 정확히 입력하면 해당 장치를 선택한다. 비워두면 시스템 기본 장치를 사용한다. 조용한 입력은 보정한 뒤 Whisper로 전달하며 `Boost Quiet Input`을 꺼서 원본 입력과 비교할 수 있다. 극히 낮은 신호는 인식 대신 마이크 확인 메시지를 표시한다. 보정은 주변 잡음도 증폭할 수 있다. 녹음 음성 파일은 저장하지 않는다.

### 마이크 진단

`VoiceIntegrationTest` 씬에서 `Voice Movement Integration` 컴포넌트의 `Enable Voice Diagnostics`를 켜고 Play한다. 게임 시작 후 `R`을 누른 채 발화한 뒤 떼면 마지막 녹음을 메모리에 보관한다. 인식이 끝난 뒤 텍스트 명령창을 닫고 다음 키를 누른다.

- `F10`: 같은 녹음을 원본과 보정본으로 각각 Whisper에 전달해 인식 결과와 시간을 Console에 출력한다. 비교 결과는 직원 명령으로 실행하지 않는다. 두 번 순차 처리하므로 시간이 걸린다.
- `F11`: 같은 녹음을 같은 음량 설정으로 두 번 인식해 단어 문맥 적용 전후 결과를 Console에 출력한다. 이 비교도 직원 명령을 실행하지 않는다.

Console의 `마이크`, `녹음 진단`, `진단 인식 원본`, `진단 인식 보정본`을 함께 확인한다. 원본과 보정본의 배율이 1이면 두 입력이 같다. 입력이 너무 작아 보정을 계산할 수 없는 경우 비교할 수 없다. 녹음은 파일에 저장하지 않으며 컴포넌트 비활성화 또는 Play 종료 시 메모리에서 해제된다. 진단은 기본적으로 꺼져 있다.

`Whisper Vocabulary`에 진열·재고 등 게임 단어를 입력하면 직원 이름과 함께 문맥으로 제공할 수 있다. `Use Whisper Vocabulary`의 기본값은 켜짐이다. F11 비교는 이 설정과 관계없이 문맥 없음과 적용을 모두 시험하며, 현재 `Boost Quiet Input` 설정을 양쪽에 동일하게 적용한다. 문맥은 인식 결과를 보장하지 않으며 말하지 않은 단어를 유도할 수 있으므로 서로 다른 발화를 반복 비교한다.

## 기존 단독 데모

1. `Scenes/EmployeeVoiceDemo.unity`를 연다.
2. Hierarchy에서 `Employee Voice Demo`를 선택한다.
3. Inspector에 이 폴더의 `Assets/ggml-small-q5_1.bin`과 `Assets/qwen2.5-1.5b-instruct-q4_k_m.gguf` 경로가 설정되어 있다. 다른 모델을 쓰려면 절대 경로 또는 프로젝트 루트 기준 상대 경로로 변경한다.
4. Play 후 Game 화면에서 `Record command`를 눌러 말하고 `Stop recording`을 누른다. 녹음 최대 길이에 도달하면 자동으로 종료된다. 텍스트를 입력하고 `Send text command`로 시험할 수도 있다. 예: `민수야 3번 테이블 치워`, `지수야 3번 테이블 치워`.
5. Console에서 `[EmployeeVoice] Recognized`, `Intent`, `action` 메시지를 확인한다. Inspector에서 직원 이름, 성격, 스트레스, 피로도, 충성도를 조절할 수 있다.

## 명령과 직원 상태

지원 업무는 주문받기, 음식 제공, 테이블 청소, 쓰레기 버리기, 재고 보충이다. 명령 해석은 LLM이 담당하고 명시적인 업무·대상 단어를 별도로 확인한다. 부정, 복합 지시 또는 확인되지 않은 표현은 추측하지 않고 재설명을 요청한다. 예를 들어 `3번 테이블 치워`는 청소로 처리하고 `저것 좀 해`는 재설명을 요청한다. 이 단어 기반 검사는 보수적이므로 의미가 분명한 다른 표현도 재설명을 요청할 수 있다.

테이블 정리 명령은 요청 업무와 직원 행동을 분리한다. `3번 테이블 치워`는 `CLEAN_TABLE` 요청과 대상 `3`으로 해석하되, 직원 행동은 `CLEAN_TABLE`, `THROW_AWAY_TABLE`, `IGNORE_COMMAND`, `COMPLAIN`, `REST` 중 하나로 선택한다. 테이블 번호가 명시되지 않으면 대상으로 `unspecified`를 기록하며 추측하지 않는다.

데모에는 기본 직원 `민수`, `지수`와 3번 테이블 하나가 있다. Inspector의 `personality`와 `secondEmployee`에서 이름과 성격·감정을 각각 설정한다. 기존 씬의 `Employee 1` 기본값은 플레이 중에만 `민수`로 표시된다. 이름이 없거나 여러 직원 이름이 있으면 재지정을 요청한다. 테이블 업무는 3번을 명시해야 하며 존재하지 않거나 이미 창고로 옮겨진 테이블은 작업할 수 없다.

`CLEAN_TABLE`은 임시 직원이 테이블로 이동한 뒤 색을 초록색으로 바꾸고, `THROW_AWAY_TABLE`은 직원이 테이블로 이동한 뒤 테이블을 창고 위치로 옮긴다. 테이블이 창고로 이동하면 Play를 중지하고 다시 실행해야 복구된다. 불평·무시·휴식은 Console에 반응을 출력한다. 직원 또는 테이블이 작업 중이면 중복 작업을 거부하고 중지 시 테이블 예약을 해제한다. 이는 실제 게임 에셋이나 내비게이션이 아닌 임시 데모다.

완료된 청소·테이블 이동은 피로도를 5 올리고, 휴식은 피로도를 20 낮춘다. 불평은 스트레스를 5 낮춘다. 테이블을 잘못 옮기면 해당 직원의 스트레스가 10, 동료의 스트레스가 5 증가한다. 값은 0~100으로 제한되며, 중단하거나 실패한 업무는 상태를 바꾸지 않는다. 이 수치와 동료에게 영향을 주는 이벤트는 게임 재미를 검증하기 위한 임시 규칙이다.

LLM은 직원의 성격·상태를 보고 다섯 후보 중 하나를 제안하고, 제안의 가중치에 1.25배를 적용한다. 최종 선택은 성실함(`diligence`), 문자 그대로 받아들이는 정도(`literalness`), 게으름(`laziness`), 스트레스·피로·충성도를 반영한 가중 무작위 방식이다. 이 값들은 Inspector의 Personality에서 0~100으로 조절한다. 실수나 감정 행동이 매번 일어나거나 특정 성격에 절대적으로 고정되지는 않는다. 수치는 플레이 테스트를 위한 초기값이며 향후 조정이 필요하다. LLM이 후보 밖 결과를 반환하거나 판단에 실패하면 실행하지 않고 재시도를 요청한다.

다른 네 업무는 기존 임시 상태 규칙을 유지하며 실제 실행 없이 판단 결과와 분류만 Console에 출력한다. 동일한 명령과 상태라도 가중 무작위 선택으로 결과가 달라질 수 있다.

음성 인식 및 명령 해석 시간은 Console의 `elapsed_ms`에 밀리초로 출력한다. `managed_bytes`는 .NET 관리 메모리, `unity_allocated_bytes`는 Unity 관리 할당량의 스냅샷이다. 전체 프로세스 메모리 또는 GPU 메모리를 의미하지 않는다.

## 플레이어 배포용 모델 경로

모델을 빌드에 자동으로 동봉하거나 자동 다운로드하지 않는다. Windows 플레이어 실행 시 `Application.persistentDataPath/EmployeeVoiceModels/`에 아래 파일을 별도로 제공한다. 실제 경로는 회사·제품명 설정에 따라 달라지며, 파일이 없으면 Console에서 필요한 전체 경로를 확인할 수 있다.

- `ggml-small-q5_1.bin`
- `Qwen3.5-2B-Q4_K_M.gguf` (통합 테스트 씬)
- `qwen2.5-1.5b-instruct-q4_k_m.gguf` (기존 단독 데모 또는 비교 시)

에디터에서는 씬의 프로젝트 상대 경로를 사용하고 플레이어에서는 위 폴더의 동일한 파일명을 사용한다. 이 경로 처리는 구현됐지만 플레이어 빌드와 다른 PC에서의 모델 전달·구동은 아직 확인하지 않았다. LLMUnity의 네이티브 라이브러리 포함 여부와 플랫폼별 마이크 권한도 배포 빌드에서 검증해야 한다. 모델 및 라이브러리 고지 준비 내용은 `THIRD_PARTY_NOTICES.md`를 확인한다.

직원과 테이블은 플레이 중 생성되는 임시 오브젝트다. 모델이 로딩 중이거나 파일, 마이크, LLM을 사용할 수 없으면 상태 메시지를 표시한다. Unity 에디터에서 전체 동작과 충돌·이동을 확인해야 한다.
